# Machine Learning Technical Documentation (Explainability Milestone)

This document describes the model selection, dataset metrics, evaluation parameters, and feature importance interpretations for the Solar & Wind Deployment Intelligence Platform. This documentation supports the upcoming Investment Analysis module.

---

## 1. Selected Machine Learning Models

* **Site Suitability Score Predictor (Regression)**: 
  - **Model**: `GradientBoostingRegressor` (from `scikit-learn`)
  - **Parameters**: `n_estimators=100`, `random_state=42`
* **Technology Recommendation Predictor (Classification)**:
  - **Model**: `DecisionTreeClassifier` (from `scikit-learn`)
  - **Parameters**: `random_state=42`

---

## 2. Dataset Summary

* **Total Samples**: `2,000`
* **Data Sources**:
  - **Historical Database Features**: 3 site records queried directly from the `features` database table.
  - **Synthetic Fallback Augmentation**: 1,997 samples generated using realistic statistical distributions of meteorological (irradiance, wind speed, temp, humidity) and physical (elevation, slope, costs) factors to prevent overfitting on limited database examples.
* **Target Labels**: Generated by executing the existing physics-based `Site Scoring Engine` and `Deployment Recommendation Module` on the feature profiles.
* **Splitting Strategy**: 80% Training set (1,600 samples), 20% Test set (400 samples).

### C. Domain Justification & Interpretation
* **Technology Classification**: Perfect alignment with domain knowledge. The decision boundaries between "Solar", "Wind", "Hybrid", and "None" are strictly determined by the wind speed and solar irradiance thresholds. The Decision Tree Classifier correctly learned that physical features (slope, road/grid distance) do not influence *which* technology is recommended, only *if* a site is suitable overall.
* **Suitability Score**: `slope` is the most influential feature (49.36%). In the scoring engine, `normalize_slope(slope)` uses a sharp step-down filter: any slope exceeding bounds receives a 0 score and heavily penalizes the overall site score. Thus, slope acts as a primary reject/accept indicator. `wind_speed` and `solar_irradiance` have high secondary importances because they determine the Resource score (which carries 35% of the overall scoring engine weight).

## 5. Model Limitations & Assumptions

* **Rule Mimicry**: The models are currently trained on synthetic labels mapped directly from the physics-based scoring engines. They represent a baseline emulator but do not capture real-world operational anomalies not present in the code rules.
* **Scale Invariance**: Decision Trees and Gradient Boosting are scale-invariant, meaning they do not require strict input scaling, but they can be sensitive to small perturbations near threshold boundaries.

## 6. Future Improvements
* **Active Feedback Loop**: Implement automatic online retraining as developers enter actual site suitability findings and outcomes into the database.
* **Probability Estimates**: Shift from deterministic classifications to class probabilities (e.g. using Random Forest `predict_proba`) to provide confidence percentage margins directly to the Investment Analysis module.
